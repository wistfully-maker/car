# 对方导航配置安全复现设计

## 1. 目标

在不覆盖现有导航配置的前提下，建立一套来自另一参赛组的独立导航基线，验证同一张
静态地图、同型号小车采用对方完整导航参数后，能否通过当前反复失败的直角弯。

本阶段只验证导航基线，不接入任务编排器，也不以比赛速度为验收目标。

## 2. 已确认事实

- 对方 `002.pgm` 与本项目 `map.pgm` 的 SHA256 完全一致。
- 两份地图的分辨率、原点和占用阈值一致。
- 通过 `roslaunch --dump-params` 验证，对方最终使用：
  - `global_planner/GlobalPlanner`
  - `teb_local_planner/TebLocalPlannerROS`
  - `controller_frequency: 15.0`
  - `planner_frequency: 5.0`
- 对方 GlobalPlanner 与当前配置主要存在两个差异：
  - `orientation_mode: 0`，当前为 `1`
  - `lethal_cost: 253`，当前为 `254`
- 对方雷达静态 TF 为 `x=0.11, z=0.13, yaw=0`，与当前配置差异明显。
- 对方 TEB 使用 `point` 车体模型并配置了较高速度，因此不能无保护地直接执行完整路线。

## 3. 配置隔离

新增独立的 `other_team_baseline` 配置，不修改或覆盖当前 DWA、TEB 安全配置。基线至少
包含：

- 雷达静态 TF；
- AMCL；
- GlobalPlanner；
- TEB；
- 全局与局部 costmap；
- move_base 通用参数；
- 独立启动入口。

启动入口必须显式选择该基线，不允许其成为现有导航启动文件的默认值。切回当前配置
不需要恢复文件或执行 Git 回退。

## 4. 参数复现边界

为判断对方配置是否确实能够通过拐弯，算法行为参数按对方文件复现，包括：

- GlobalPlanner 路径参数；
- AMCL 运动模型和激光模型；
- TEB 优化权重、障碍距离、采样和可行性检查参数；
- TEB 的 `point` 车体模型；
- costmap 分层、膨胀和更新参数；
- 15 Hz 控制频率与 5 Hz 全局规划频率；
- 雷达静态 TF。

第一次实车测试仅通过独立安全覆盖层限制：

- 最大前进速度不超过 `0.20 m/s`；
- 最大后退速度不超过 `0.10 m/s`；
- 最大角速度不超过 `0.40 rad/s`。

除安全限速外，不混入当前项目的 TEB 权重、矩形 TEB footprint 或路径朝向参数。这样
既能保留对方配置的主要行为，又避免第一次测试直接使用 `2.4 m/s`。

## 5. 验证流程

### 5.1 静态验证

启动前确认：

- launch XML 和 YAML 可以解析；
- 最终局部规划器是 TEB，全局规划器是 GlobalPlanner；
- 地图校验值与对方地图一致；
- 雷达只存在一个静态 TF 发布者；
- 底盘、雷达、AMCL 和 move_base 不存在重复节点；
- 实际速度上限来自安全覆盖层。

### 5.2 定位验证

在起点初始化 AMCL 后，记录：

- 当前 AMCL 位姿和协方差；
- 激光点与地图墙线在 5 cm、10 cm 范围内的匹配比例；
- 自动搜索得到的最佳位姿修正量。

只有定位结果没有明显错误时才发送导航目标。对方雷达 TF 若使匹配度比当前配置更差，
立即停止本轮，不通过调 TEB 掩盖定位问题。

### 5.3 实车验证

第一轮只发送到此前失败拐弯附近的受控目标：

- 车旁必须有人观察；
- 保留取消目标和零速度停车命令；
- 记录 `/scan`、`/odom`、`/amcl_pose`、全局路径、局部路径、`/cmd_vel` 和
  move_base 状态；
- 接近墙、定位跳变或持续无有效控制时立即取消；
- 不在第一轮直接执行完整路线。

通过拐弯后，重复相同路线至少三次。三次均无碰撞、无人工接管后，才允许测试完整
路线。

## 6. 结果判定

可能出现三类结果：

1. 对方基线可以通过：继续逐项恢复矩形 TEB footprint、合理速度和较小 TF 容差，
   每次只修改一类参数。
2. 定位匹配明显改善但仍无法通过：重点分析 GlobalPlanner 路径形状与 TEB 可行性，
   不再怀疑地图文件不同。
3. 定位匹配没有改善或更差：说明雷达安装外参或小车个体差异不能直接复制，应重新
   标定本车雷达 TF。

## 7. 后续优化顺序

基线跑通后按以下顺序提高安全性：

1. 将 TEB `point` 模型改为实车矩形 polygon；
2. 将 `transform_tolerance: 10` 降到可解释范围；
3. 校准底盘 watchdog 与实际控制周期；
4. 在不降低通过率的前提下提高速度；
5. 再调整障碍距离、膨胀和路径权重。

任何一步导致拐弯失败，都回到上一组已验证参数，不同时修改多个变量。
