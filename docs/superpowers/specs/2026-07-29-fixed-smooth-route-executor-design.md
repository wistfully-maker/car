# U-CAR 固定平滑路线执行器设计

## 1. 背景

当前从比赛发车点 P 到物品领取区二维码观察点的导航，先后使用过 DWA、TEB、
多组局部规划参数和拐点监督器。实车仍出现直线蛇形、反复横移或倒退、连续弯卡住、
局部规划不可行以及碰墙等问题。

这段比赛路线的地图、起点、墙体和终点均固定。继续让局部规划器在每个控制周期重新
选择轨迹，会把 AMCL 波动、局部代价地图变化和优化器局部解带入本应重复一致的固定
路线。本设计改用预先生成并验证的固定平滑路线，由专用闭环控制器跟踪。

## 2. 已确认输入

- 地图：`ucar_nav/maps/map.yaml` 和对应 `map.pgm`。
- 地图分辨率：`0.05 m/pixel`。
- 地图坐标系：`map`。
- 起点 P：
  - `x = 0.0`
  - `y = 0.0`
  - `yaw = 0.0`
- 二维码观察点：
  - `x = -1.40219`
  - `y = -0.627908`
- 最终朝向：面向距离起点最近的物品领取区墙面，当前航点四元数对应
  `yaw ≈ -3.0878 rad`。
- 到达后二维码模块从该朝向开始逆时针旋转扫描。
- 正常路线禁止倒退。
- 第一阶段只覆盖“P 点到二维码观察点”。

## 3. 核心决策

固定路线正常执行时不使用：

- `DWAPlannerROS`
- `TebLocalPlannerROS`
- `move_base` 的局部轨迹控制
- 现有拐点监督器的强制 `TURNING`

继续使用：

- `map_server`
- AMCL
- `map -> odom -> base_link` TF
- 里程计
- 激光雷达
- 底盘驱动

TEB 和现有导航配置保留，不删除，作为其他非固定路线或对比测试的备用方案。固定
路线执行器与 TEB 不得同时向 `/cmd_vel` 发布速度。

## 4. 总体架构

```text
静态地图 + 起终点
        |
        v
离线路线生成与碰撞验证
  栅格膨胀 -> 参考路径 -> 关键点 -> 分段三次 Bézier -> 速度曲线
        |
        v
固定 route.yaml
        |
        v
fixed_route_executor
  AMCL/TF + odom -> 进度估计 -> 前视跟踪 -> 速度命令
        |
        v
lidar_safety_guard
        |
        v
/cmd_vel -> base_driver
```

## 5. 路线生成

### 5.1 障碍膨胀

离线读取 PGM 和 YAML，将占用栅格按以下尺寸膨胀：

- 小车矩形 footprint；
- 定位和控制误差余量；
- 可配置附加安全距离。

路线采样点以及采样点之间的车体扫掠区域均不得进入膨胀障碍。

### 5.2 参考路径

在膨胀地图上，从固定起点到固定观察点离线搜索无碰撞参考路径。搜索结果只用于生成
初稿，不在比赛运行时重新规划。

参考路径需经过人工检查，确保选择的是比赛预期走廊，不走不必要的绕行。

### 5.3 关键点和曲线

从参考路径提取：

- 长直线中心线；
- 走廊入口和出口；
- 显著转向点；
- 连续紧邻弯道。

相邻直线使用分段三次 Bézier 曲线连接。每段曲线约束：

- 起点和终点位置；
- 入弯切线；
- 出弯切线；
- 控制点不得进入墙体安全区域；
- 相邻曲线位置和切线连续。

对于中间直线很短的连续弯，不分别强行放置两个大圆角，而是联合调整控制点，使其
成为一段连续、可跟踪且不越出走廊的曲线。

### 5.4 固化结果

生成的 `route.yaml` 至少保存：

- 路线名称和版本；
- 地图文件校验值；
- 起点与终点；
- 稠密采样点；
- 每点累计里程；
- 每点期望切线方向；
- 每点曲率；
- 每点速度上限；
- 直线段、曲线段和终点段标记；
- 车体与墙面的离线最小余量。

## 6. 速度规划

速度曲线在开发阶段离线生成：

- 长直线平滑加速；
- 根据前方曲率和剩余距离提前减速；
- 连续弯之间不强制停车；
- 出弯后平滑加速；
- 接近二维码观察点时平滑减速至零；
- 任意正常点的期望前进速度不得为负。

第一版优先连续、稳定地完成路线。实车验证后再提高直线速度、曲线速度和加速度。

## 7. 闭环跟踪控制

### 7.1 输入

- `map -> base_link` 当前位姿；
- `/odom` 连续运动信息；
- 固定路线；
- 激光雷达安全状态；
- 启动、取消和急停命令。

### 7.2 进度估计

控制器在当前进度附近寻找最近路线点，进度只允许在有限窗口内前进，避免定位波动
导致跳到相邻走廊或越过连续弯。

若当前位姿与路线距离超过可配置阈值，停车并报告偏离路线，不允许通过倒退自动恢复。

### 7.3 控制输出

直线段：

- `linear.x` 沿车头向前；
- `angular.z` 修正航向误差；
- `linear.y` 只用于消除小横向误差，并设置较小上限；
- 不允许负 `linear.x`。

曲线段：

- `linear.x` 按速度曲线前进；
- `angular.z` 由曲率前馈和航向误差反馈组成；
- `linear.y` 可按横向误差充分修正，不采用直线段的小上限；
- 不允许负 `linear.x`。

所有命令最终执行硬约束：

```text
linear.x >= 0
```

控制器不得通过“先前进、再倒退”调整位置。

### 7.4 终点

接近二维码观察点时同时收敛：

- 位置误差；
- 最终航向误差；
- 线速度和角速度。

位置和航向在稳定时间内满足容差后：

1. 连续发布零速度；
2. 发布带任务标识的到达结果；
3. 释放 `/cmd_vel` 控制权；
4. 等待二维码模块开始逆时针旋转。

## 8. ROS 包和接口

新建独立功能包：

```text
ucar_fixed_route
```

主要文件：

```text
ucar_fixed_route/
  config/
    pickup_route.yaml
    controller.yaml
  launch/
    fixed_route_navigation.launch
  scripts/
    generate_route.py
    validate_route.py
    fixed_route_executor.py
  src/ucar_fixed_route/
    map_geometry.py
    bezier_route.py
    speed_profile.py
    route_tracker.py
    safety.py
  test/
```

第一版接口：

- `/task/pickup_navigation_goal`：接收任务编排器的领取区导航目标；
- `/task/pickup_arrived`：发布带原任务标识的到达或失败结果；
- `/ucar_fixed_route/state`：发布
  `IDLE`、`RUNNING`、`ARRIVED`、`BLOCKED` 或 `ERROR`；
- `/ucar_fixed_route/diagnostic`：发布路线进度、横向误差、航向误差、期望速度和
  最近障碍距离；
- `/ucar_fixed_route/start`：`std_srvs/Trigger`，仅用于脱离编排器的实车调试；
- `/ucar_fixed_route/cancel`：`std_srvs/Trigger`，停车并取消当前路线。

接口与现有 `task_orchestrator` 最小集成协议保持兼容，但本阶段不修改编排器。

## 9. 安全和所有权

- TEB、DWA、拐点监督器和固定路线执行器不能同时拥有 `/cmd_vel`。
- 启动时检查其他速度发布者；发现冲突则拒绝运行。
- 雷达安全层独立于正常路线跟踪，危险距离内立即输出零速度。
- TF超时、AMCL跳变、路线偏离、控制周期超时或路线文件不匹配时停车。
- ROS关闭或节点异常退出时发送零速度。
- 不实现自动倒退恢复。

## 10. 测试与验收

### 10.1 离线测试

- 地图坐标和像素坐标转换正确；
- Bézier端点、切线和连续性正确；
- 速度、加速度无突变；
- 全路线车体扫掠不与膨胀障碍相交；
- 所有正常控制输出满足 `linear.x >= 0`；
- 进度不会跳到相邻走廊；
- 最终姿态为指定观察方向。

### 10.2 分级实车测试

1. 低速测试第一段直线；
2. 低速测试第一个连续弯；
3. 低速测试完整连续弯；
4. 低速完成起点到观察点；
5. 分别提高直线和弯道速度；
6. 连续至少三轮完整通过。

每轮记录：

- Git提交；
- 路线版本；
- AMCL初始位姿；
- 实际轨迹；
- 横向和航向误差；
- 最小墙距；
- 完成时间；
- 是否人工急停。

### 10.3 第一阶段验收

- 从固定起点自主启动；
- 直线不明显蛇形；
- 连续弯中不倒退、不原地反复调整；
- 不碰墙；
- 到达二维码观察点；
- 最终面向指定墙；
- 停车后二维码模块可取得底盘控制权；
- 相同初始条件下连续三轮行为基本一致。

## 11. 非目标

本阶段不实现：

- 任意起终点的通用导航；
- 动态障碍绕行；
- TEB参数动态切换；
- 失败后的自动倒退脱困；
- 二维码旋转搜索本身；
- 任务编排器修改；
- 二维码区域之后到各车间的路线。

后续固定目标车间坐标确认后，可复用相同路线生成和执行框架增加其他路线。
