# Stop 第二阶段航点记忆最小优化设计

日期：2026-08-11
分支：`codex/stop-phase2-integration`

## 1. 目标

在不改变现有 ROS 接口、OCR 扫描和 Stage 0–5 停车算法的前提下，让 stop 在搜索实际物品目标车间时记住各航点识别到的车间名称。实际物品停车完成、仿真目标下发后，若已知仿真车间所在航点，优先直接导航到该航点；到达后仍重新执行完整 OCR 扫描、对准、激光靠近和停车。

实际物品目标与仿真物品目标保证属于不同车间。

## 2. 当前问题

当前代码只有一个 `sim_point_index`：

- 第一阶段只会按当时的 `sim_keyword` 顺带记录一个仿真航点；
- 第一阶段开始时，stop 尚未收到本任务权威的仿真目标，`sim_keyword` 可能只是默认值；
- 未保存其他已识别车间，也未记录完整扫描过的航点；
- 仿真目标未知时可能重复扫描实际停车点；
- 从较早航点跳转后若识别失败，没有明确的无重复兜底顺序。

## 3. 范围和非目标

本次只修改 stop 内部的航点选择逻辑及其测试。

保持不变：

- `task_orchestrator`、导航交接和 stop protocol 的 topic 名称与 JSON 合同；
- 三个固定航点坐标；
- 第一阶段初始搜索顺序 `1 → 2 → 3`；
- 每个航点的旋转 OCR 扫描次数和识别逻辑；
- 已有导航失败重试；
- Stage 0–5 相机、LiDAR、PCA、横移和停车行为；
- 实际停车后等待全局播报及仿真目标放行的门控。

明确不实现：

- 缓存或重放相机角度、板面方向、LiDAR 距离、PCA 法向量；
- 到达已知仿真航点后跳过 OCR；
- 新增 ROS topic、消息类型或协议字段；
- 计算新的停车预备点或改变 move_base/TEB 参数。

## 4. 航点记忆模型

增加任务内存，任务启动时清空：

```python
workshop_waypoint_candidates = {
    "电子产品生产车间": {0},
    "日用品加工车间": {1},
}
scanned_waypoints = {0, 1}
real_point_index = 1
phase2_route = []
phase2_route_cursor = 0
```

规则：

1. 每次收到 OCR 结果时，将所有能映射到 `WAREHOUSE_MAP` 标准车间名的文本记录为当前航点的候选。
2. 记录候选不改变现有扫描节奏，不增加驻留或确认动作。
3. 同一车间若只在一个航点出现，该位置可用于优先跳转。
4. 同一车间若在多个航点出现，视为位置冲突，不选择其中任何一个作为直达目标；第二阶段走兜底搜索顺序。
5. 单帧误识别最多造成一次额外导航。到达后仍重新 OCR，因此不会依据缓存盲目停车。
6. 当前航点旋转次数耗尽或当前目标在该点确认后，将该航点加入 `scanned_waypoints`。

## 5. 第二阶段路线算法

收到权威仿真目标并准备切换第二阶段时，根据标准车间名构造一次性的 `phase2_route`。

### 已知唯一位置

```text
[缓存的仿真航点]
  + [尚未列入且不是实际停车点的其他航点]
```

缓存航点优先；若重新扫描没有找到目标，继续剩余航点，不重复导航，也不回到已知属于实际目标的停车点。

### 位置未知或冲突

```text
[实际停车点之后尚未扫描的航点]
  + [实际停车点之前已扫描过的航点]
```

这样优先继续 `1 → 2 → 3` 的自然顺序，同时允许 OCR 首轮漏识别后的有限兜底。实际停车点因目标保证不同而排除。

`current_point_index` 继续表示当前实际航点；第二阶段通过路线游标选择下一个索引。正常扫描耗尽和导航重试耗尽都调用同一个“推进路线”辅助函数，避免一处按列表推进、另一处仍执行 `index += 1`。

## 6. 示例

### a 在航点 2，b 在航点 1

```text
航点1：扫描不到a，识别并记住b
航点2：识别a，执行第一次停车
收到b目标：构造路线 [1, 3]
导航回航点1：重新 OCR，确认b，执行第二次停车
```

### a 在航点 1，b 在航点 3

```text
航点1：识别a，执行第一次停车
收到b目标：缓存未知，构造路线 [2, 3]
航点2重新扫描无果 → 航点3确认b并停车
```

### a 在航点 3，b 在航点 2

```text
航点1扫描 → 航点2记住b → 航点3停放a
收到b目标：构造路线 [2, 1]
返回航点2重新扫描并停车
```

## 7. 失败和安全行为

- 候选位置冲突：不直达，使用兜底路线。
- 缓存位置重新扫描未找到：推进到路线中的下一个航点。
- 导航 ABORTED：保持现有同航点重试一次，再推进路线。
- 第二阶段路线全部耗尽：保持现有 `failed:not_found` 终态、零速度和失败上报。
- 任意阶段任务取消：保持现有取消、零速度和终态去重行为。

## 8. 测试要求

按 TDD 增加纯逻辑或 AST/回调回归测试，至少覆盖：

1. 第一阶段记录任意标准车间到当前航点，不依赖预先知道 b；
2. 同一车间多航点冲突时不直达；
3. `a=2, b=1` 的路线为 `1 → 2 → 1`；
4. `a=1, b=3` 的路线为 `1 → 2 → 3`；
5. `a=3, b=2` 的路线为 `1 → 2 → 3 → 2`；
6. 已知 b 到达后仍从 OCR Stage 0 开始，未直接进入停车；
7. 缓存位置识别失败后按路线推进且不重复航点；
8. 导航重试、两次停车事件和现有协议测试保持通过；
9. task_orchestrator、stop、llm_spark 全量回归及车端 `catkin_make` 通过后才允许实车验收。
